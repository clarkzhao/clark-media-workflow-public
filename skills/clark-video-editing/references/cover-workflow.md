# 旅行封面：候选、定稿与四种比例

## 参考风格与本次素材

可复用的系列视觉风格：深蓝笔刷小标签、米白粗体略倾斜的大字、少量黄色下划线，以及倾斜的白边双人照片卡。山水可作背景，熊猫或地标也可成为主体。它是可复用的系列风格；用户有新要求时调整，不把固定配色、熊猫或旧标题当作所有项目的内容。

私人风格样图仅保存在本地 `../assets/cover-style/`，具体索引由被忽略的 `local-machine.private.md` 或当前项目记录提供。换机器缺失时从本地备份或项目已有封面定位，不假装已查看。

先用 `view_image` 查看实际引用的样图和当前原照片。样图里的旧人脸、服装、地点、天气及文字不能移植到新旅程。配图从本次照片或原视频清晰抽帧中选；需要体现熊猫、地标、双人关系时，先比较主体清楚、人物好看、手势完整、适合小图辨识的素材。不要为了漂亮捏造旅行景色、晴天或实际未见的对象。

## 先选配图，再扩展画幅

1. 提取当前封面的准确文案：小标签、主标题、地点副标题。将评审要求与画面文字分开；“可以期待一下”、制作技术名、提示词等工作指令不进入封面。
2. 已认可字体时保留字形风格，只尝试不同配图。可做山水、动物、地标和组合等少数有区分的横版候选，不把四种比例误当四个设计方向。
3. 用候选编号及同页大图提供评审。用户选定一版后沿用选择，不再重复询问；只有尚未选定且需要选择时，才把候选作为实际评审结果交给用户。
4. 选定后交付 **16:9、4:3、3:4、9:16** 四个独立文件。已有正确横版直接保留，后三版以选定封面作风格参考，同时带入当前原照片，逐版重新构图。

本次文案与主体按当前项目确定。候选选择和评审记录保存在项目中，不写入通用模板。

## 多比例构图与生成

使用当前会话技能目录列出的 `imagegen` 技能及内置工具（它不随本仓库分发，按实际安装位置读取）；具体工具约束以当前会话提供的说明为准。每个版本一次调用，不为批量生成自动改成 CLI、另装模型或调用云端配音。全部目标有本地路径时用 `referenced_image_paths`，先查看输入；不用同时提供 `num_last_images_to_include`。输出保持不透明背景。

输入角色写清楚：第 1 张是历史风格或用户选定封面，第 2 张是本次主体原照片，第 3 张是本次双人原照片。候选生成与比例扩展的提示词模板在 `../assets/cover-prompts.json`；人物、动物和地标保真要求是目标，必须用实际输出核查，不能因提示词写了“精确保留”就宣称生成图像素未变。

- **16:9**：横版建立整体视觉，标题与主体分区，双人照片卡保持可辨识；已选定且无需修改时不重新生成。
- **4:3**：压缩横向空间，调整标题字号、主体和照片卡位置，避免副标题与主体相撞。
- **3:4**：标题移到上部，主体占中部，照片卡靠下；按标题长度分行，不能丢字或硬挤横版。
- **9:16**：上部留文字、中部展示主体、下部安排照片卡；兼顾手机界面可能遮挡的两侧与底部，不裁掉脸和有意义的手势。

每版看完整大图，再以缩略图检查：文字是否准确、主次是否清楚、脸和手是否自然、熊猫或地标是否忠实、是否出现水印或无关人物特写。不同画幅可以换行和移动元素，但字体、配色与主体选择须成系列。发现单处问题定向修订该版，不重做已通过版本。

## 可复用提示词与本地交付

脚本 `../scripts/cover_pack.py` 不生成、裁切或修改图片，只生成带参数的提示词，并验证、复制四张完成图，输出 PNG/JPEG/WebP 原格式文件、带尺寸和 SHA256 的 `cover_manifest.json` 与可直接打开的预览下载 HTML。原图和内置工具默认保存的生成图保留在原处。

运行脚本需 Python 3.11+ 及 Pillow；优先复用工作区已有依赖运行时，下例的 `python` 代表已选定并核查的解释器，不能默认系统 Python 满足版本。脚本用于完整四版交付；用户只要部分比例时按实际范围交付，无须为满足脚本补齐四版。

生成提示词（路径使用当前项目绝对路径；调用 `image_gen` 仍由 agent 完成）：

```powershell
python <技能目录>/scripts/cover_pack.py prompts --label "旅行记录" --title "本次标题" --subtitle "本次地点" --hero-subject "本次主体" --style <已查看的参考图> --hero <主体原照片> --couple <双人原照片> --output <项目目录>/exports/cover_prompts.json
```

`prompts` 输出候选用的共同提示词与四种比例的提示词。先完成候选选择；扩展比例时把参考图换为用户选定的封面，再生成该阶段的提示词记录，不调用工具重新制作已选横版。

交付配置是 JSON：`title` 是本次标题，`selected_candidate` 是已确认编号，`images` 按 `16:9`、`4:3`、`3:4`、`9:16` 四个键给出完成图的路径；可用 `prompt_record` 指向本次生成提示词 JSON。相对路径以配置文件目录为基准，优先用绝对路径。

```powershell
python <技能目录>/scripts/cover_pack.py deliver --config <项目目录>/cover_delivery.json --out <项目目录>/exports/cover_final_v1
```

工具输出可能有不足 1 像素的比例舍入，例如 1672×941 和 941×1672。脚本记录实际尺寸与 `ratio_exact`，仅接受 1 像素以内的舍入误差，不能宣称近似值是数学上精确比例。平台要求严格尺寸时使用 `--strict-ratio` 检验，按要求在图像制作环节处理，再交付；脚本不会偷偷拉伸或裁切。

脚本拒绝覆盖已有交付文件。修订时使用新的版本目录，保留旧版和实际生成记录。用户选择、源图角色、工具模式、完整提示词和最终路径留在项目中，技能只保留模板及明确标记的历史风格样图。

最终给出四版可预览和下载的入口，并链接实际文件。网页仅显示观众能理解的标题、比例和下载操作，不塞技术说明。按需要在 Codex 打开预览页；已有本地服务器时复用，不为封面新建无关服务。
